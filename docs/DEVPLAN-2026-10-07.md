双机双 AI 并行开发模式与协作公约。分工草案之外的最终分配由用户拍板；两机开工前都必须读完

## 0. 模式结论

**可行，有四个前提**：契约先行、地基先行、文件分治、单点集成。本仓库的合并风险点集中
在少数热点文件（`src/api.ts`、`public/admin/app.js`、`schema.sql` ⇄ `src/db.ts` 双处同步、
settings 键），且积分/排行榜的数据源就是 `members.points`（依赖会员地基）。裸并行必然撞车，
按下述公约并行则两机互不阻塞。

## 1. 开工前用户必须拍板的三件事（ROADMAP「待拍板决策」）

## 3. 协作机制

1. **契约先行**：开工第一件事，两机共同确认 API 端点清单（路径 / 方法 / 入参 / 出参 JSON
   形状）、settings 新键表、主题渲染参数（registry.ts 命名类型扩展），登记进本文档附录
   或随 Step 0 提交；之后改契约必须两端知情，不许单方面变（**已定稿：文末附录 A 契约 v1 =
   B 提案 7011fc0 + A 会签，双方此前的 v0 / v1 草案同时作废**）
2. **地基先行**：A 的 Step 0 地基提交是 B 的开工闸门；B 在此之前只做不碰表结构的纯 UI
   骨架与 fixture
3. **分支模型**：`main` 为集成分支；两机各自工作分支 `dev/a-*`、`dev/b-*`，随时推 origin
   互读进度；**合并回 main 只由树莓派（集成机）执行**
4. **节奏**：小步快跑——每完成一个可测试切片即 commit + push origin；开工前一律
   `git pull --rebase origin <分支>`；提交信息沿用前缀中文风格
5. **质量门禁**：每序列提交前 `npm run typecheck` + `npm test` 必须过；任何进 main 的合并
   在树莓派上加跑 `npm run smoke`；UI 改动按 AGENTS.md 过 390px；新表/列必须 schema.sql
   与 db.ts 两处同步（docker-poc shim 若受影响同步并跑其 smoke）
6. **冲突仲裁**：契约 > 本公约 > AGENTS.md；同一文件同段落的竞争改动，后改方负责 rebase
   解决；schema 语义冲突一律回退到契约层重新对齐，不许两头各改一份硬合

### A1 · registry 新页面参数类型（B 持类型定义，A 产出数据）

`src/themes/registry.ts` 新增（`MemberView` / `RankEntryView` 同时供 render.ts 复用）：

```ts
export interface MemberView {
  nickname: string
  tier: 'normal' | 'coffee' | 'top'
  points: number
  email?: string
  avatarUrl?: string   // P1 预留，可不传
  createdAt?: number
}
export interface RankEntryView {
  rank: number          // A 排好序的名次（1 起）
  nickname: string
  tier: 'normal' | 'coffee' | 'top'
  points: number
  isMe?: boolean        // 当前访客本人行
}
export interface MemberData {  // /member 页
  settings: SettingsMap
  categories: CategoryLink[]
  pages?: NavPage[]
  tags?: TagCount[]
  navActive?: string           // 固定传 'member'
  member: MemberView | null    // null = 未登录 → 主题渲染登录/注册双表单
}
export interface RankData {    // /rank 页
  settings: SettingsMap
  categories: CategoryLink[]
  pages?: NavPage[]
  tags?: TagCount[]
  navActive?: string           // 固定传 'rank'
  entries: RankEntryView[]     // 已按 points 倒序；选择隐藏自己的会员由 A 过滤，不出现在列表
  total: number
  me?: RankEntryView | null
}
```

- `ThemeModule` 增加可选成员 `member?(d: MemberData): string` / `rank?(d: RankData): string`
  （**可选** + pages.ts 运行时兜底通用版，同 `page()` 现行模式，向后兼容潜在第三方主题）；
  五套内置主题全部实现
- `HomeData` 增加 `rank?: RankEntryView[] | null`：首页排行挂件数据（仅首页第一页且
  `membersEnabled` 开启时由 A 填充；缺省/null 不渲染）
- 【A 会签】`MemberView.email` **只在** `/api/member/me`（本人视角）与管理口径返回，公开面
  （排行榜 / 评论徽标）一律不含 email，防泄漏；`nickname` 口径 = `display_name || username`

### A2 · 付费墙（A 服务端截断，B 渲染遮挡层）
