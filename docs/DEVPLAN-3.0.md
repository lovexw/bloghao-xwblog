## 主题一 · 铁粉成长体系（会员 3.0）

### 为什么

现有会员体系有「积分」（comment +2 / dailyLogin +1）但没有**成长的叙事**——积分是货币，成长是身份。铁粉体系给读者一条看得见的路：**路人 → 读者 → 常客 → 铁粉 → 至交**，让「常来」本身有回报，也给站长一套运营抓手（等级专属内容、抽奖、榜单）。

### 分期

| 里程碑 | 内容 | 状态 |
| --- | --- | --- |
| **3.0-M1（本轮原型）** | 铁粉等级（纯函数判定）+ 每日签到（含连续加成）+ 活跃天数累计 + /rank 与会员卡展示 | ✅ 已入库（2026-10-21） |
| 3.0-M2 | 评论徽标显示等级名（评论 SQL LEFT JOIN 带出等级）；抽奖一期（积分兑换抽奖券、奖池 settings JSON、概率配置、后台开奖记录） | 规划 |
| 3.0-M3 | 等级门槛阅读（「铁粉可见」的段落级揭示，与付费墙 min_tier 的关系先理清——安全边界必须同样服务端截断，参考 ROADMAP C17）；铁粉周报（本周新粉 / 活跃 / 流失，发到通知渠道） | 规划 |

### 数据模型（M1 已实现）

- `members` 加 4 列（schema.sql + SCHEMA_COLUMNS 两处同步）：
  - `active_days INTEGER DEFAULT 0`——累计活跃天数（北京日口径）
  - `last_active_day TEXT DEFAULT ''`——最近活跃日（`YYYY-MM-DD` 北京墙上日期，条件更新幂等）
  - `checkin_streak INTEGER DEFAULT 0`——连续签到天数
  - `last_checkin_day TEXT DEFAULT ''`——最近签到日
- `member_points_log.reason` 扩两个值：`checkin`（每日签到 +2，ref_id = 北京日序号幂等）、`streakBonus`（连续 ≥7 天的当天额外 +1，同日幂等）。POINTS_RULES 同步登记。
- **等级不落库**：纯函数 `fanLevel(points, activeDays)` 实时判定（改等级表立即全站生效，无需迁移）。

### 铁粉等级表（fanLevel，src/fanrank.ts）

| 等级 | 名号 | 条件（同时满足） |
| --- | --- | --- |
| 0 | 路人 | 注册即得 |
| 1 | 读者 | 积分 ≥ 10 **或** 活跃 ≥ 3 天 |
| 2 | 常客 | 积分 ≥ 50 **且** 活跃 ≥ 7 天 |
| 3 | 铁粉 | 积分 ≥ 200 **且** 活跃 ≥ 21 天 |
| 4 | 至交 | 积分 ≥ 500 **且** 活跃 ≥ 60 天 |

- 签到规则：每日一次 +2 分；连续 ≥ 7 天的当天额外 +1（`streakBonus`，断签清零重来）。
- 展示位（M1）：`/rank` 榜单行带等级名、`/member` 会员卡显示当前等级 + 签到按钮 + 连续天数。
- 展示位（M2）：文章 / 微博 / 留言板评论徽标（等级名接在会员档位徽标旁）。

### 抽奖（M2 规划底稿）

- 抽奖券：积分兑换（如 20 分 = 1 券，后台可调）；每天兑换上限防刷。
- 奖池：settings JSON（奖品名 / 概率权重 / 类型：积分 / 虚拟头衔 / 兑换码文本）；**概率权重后台可配**，开奖记录落 `member_lottery_log`（新表，进备份）。
- 公平口径：概率展示诚实（前台可公开各奖概率）；「谢谢参与」必在池中；后台可一键停摆。
- 防刷：与签到同族——按会员 + 北京日限次，奖品发放走账本（reason='lottery'）。

### 红线（继承会员体系既有防线）

- 积分记账只走 `awardPoints`（日上限 / 幂等 / hasOwnProperty 校验都在里面）；新 reason 必须登记 POINTS_RULES。
- 封禁会员（status='banned'）不记分、不签到、不计活跃——所有写侧先查 status。
- 时区一律北京口径（cstDate / cstDayStart），日序号幂等沿用 (member_id, reason, ref_id) 唯一索引。

### 3.0 预备批次落地（2026-10-21，会员个性化扩展）

主题一的前置扩展先行落地（未做支付，档位由后台人工分配——支付化后续再接）：

- **自定义档位**：`src/tiers.ts` 纯函数组 + settings `memberTiers`（JSON，顺序即等级，第一档永久兜底，key 稳定、`all`/`member` 保留）。后台「设置 → 会员」可视化编辑（名称/徽标色/永久/默认天数/增删排序），编辑器「谁能看」选项随定义走。
- **默认三档更名**：普通会员（永久）/ 咖啡会员 / **付费会员**（原「顶级会员」更名，key 仍为 top，老数据无缝）。
- **档位时效**：members.tier_expires_at（NULL=永久）；后台「会员 → 分配档位」带有效期日期；过期读侧即时降级（effectiveTier），展示「已过期」。
- **认证徽标**：非基础档出带 ✓ 与档位色的徽标（SSR 评论 + 微博评论 JSON 服务端预解析），settings.showMemberBadge 全局开关。
- **会员活动中心**：/member 页四组折叠卡（浏览足迹 / 点赞 / 我的评论 / 收到的回复）；member_visits（同日去重 + 90 天滚动清理）与 member_likes 两张新表（进备份与整站包）。
- **会员回复放开**：publicComment 的 parentId 分支对会员开放（游客维持 403）；「收到的回复」按线程归账。
- **个性化设置**：memberRegOpen（注册开关）/ rankEnabled（排行榜开关）/ showMemberBadge / memberNotice（会员中心公告）。

## 主题二 · 多作者与小圈子

### 为什么

博客号的骨架（users 与 members 彻底分离、posts.author_id）天然支持多作者，缺的是**入口、边界与署名**。3.0 的路线：先把「一家人一起写」做稳（多作者），再长「小圈子」（邀请制 / 投稿流 / 圈子可见性）。

### 分期

| 里程碑 | 内容 | 状态 |
| --- | --- | --- |
| **3.0-M1（本轮原型）** | `users.role`（admin / author）+ 管理员创建作者账号 + 作者权限门槛（管理面 403）+ 文章页作者署名 | ✅ 已入库（2026-10-21） |
| 3.0-M2 | 作者个人页 `/author/:username`（按作者聚合文章 / 微博）+ 后台列表按作者筛选 + 作者资料卡（简介 / 头像） | 规划 |
| 3.0-M3 | 小圈子：邀请制作者注册（管理员发邀请码）、投稿审核流（作者发文 → 管理员审）、圈子可见性（部分文章仅圈子成员可见——与会员 min_tier 的服务端截断同族口径） | 规划 |

### 权限矩阵（M1 原型口径）

| 面 | admin | author |
| --- | --- | --- |
| 文章 / 微博 / 评论 / 媒体（读写） | ✅ | ✅（M2 起收窄为「仅自己的内容」） |
| 页面 / 分类标签 / 友链 / 编辑器工具（/admin/tools：MD 预览、粘贴净化、链接卡片） | ✅ | ✅（M2 收窄） |
| **回收站 / 设置 / 会员管理 / 统计 / 插件 / 皮肤 / 备份导出 / 整站包 / 更新中心** | ✅ | ❌ 403（回收站涉及全站内容恢复，作者删文进回收站后由站长处理；后台菜单对作者隐藏对应项） |
| 创建 / 修改其他账号 | ✅ | ❌ |

- 实现：`users.role TEXT DEFAULT 'admin'`（存量账号自动 admin）；管理员端点 `POST /api/admin/authors` 创建作者；`AUTHOR_ALLOWED_PREFIXES` 门槛挂在 `/admin/*` 鉴权之后按路径前缀放行（写死白名单常量，别做配置化——权限面越少越安全；**新增作者可用的内容端点要同步进白名单**）。
- 署名：文章页作者行取 `author_id → users.display_name`（单作者站点（全库无 author）不显示署名行，保持现状字节不变）；RSS 作者字段随 M2 作者个人页一起落地。

### 小圈子（M3 规划底稿）

- 邀请码：`invites` 新表（码 / 签发人 / 用尽即焚）；作者注册 = 管理员发码 + 邀请页自填。
- 投稿流：作者发文默认 `pending_review`（新状态，或复用 draft + 审核标记）；管理员「通过」才进发布时间线。
- 圈子可见性：沿用付费墙的服务端截断机制（`min_tier` 语义扩展或并列 `circle_only`）——**绝不复用「前端遮挡」的错误实现**。

## 主题三 · 快讯主题（news，第八套主题）

### 定位（站长的构想转译）

一个「资讯站形态」的博客皮肤，把博客号的三种内容各就各位：

- **微博 = 快讯区**：每日不定期更新，时间轴式快讯流（HH:mm 时间戳 + 密排卡片），像「今日要闻」滚动条。
- **文章 = 晚报区**：每晚一篇「今日汇总」（自动总结或手写深度），首页头条位大卡展示。
- **深度文章**：正文页走报纸排版（衬线标题、首字下沉、密排分栏感）。

### 分期

| 里程碑 | 内容 | 状态 |
| --- | --- | --- |
| **3.0-M1（本轮原型）** | 第八套主题 `news` 完整注册（八页全可渲染）+ 新闻纸风 CSS + 首页「头条 + 快讯流 + 文章列表」三段式布局 | ✅ 已入库（2026-10-21） |
| 3.0-M2 | 「今日汇总」半自动：一键把当日微博快讯聚合成草稿底稿（时间线 + 全文引用，编辑器续写），配套「晚报」发布仪式感（发布时间默认 21:30） | 规划 |
| 3.0-M3 | 快讯区增强：置顶快讯、快讯话题聚合页、RSS 快讯专 feed | 规划 |

### 布局要点（M1 已实现）

- 首页三段：**头条**（最新一篇发布文章，大卡 + 摘要）→ **快讯**（微博流，`nw-timeline` 时间轴样式，空则整段隐藏）→ **文章列表**（常规列表 + 翻页）。
- 微博页：日期分组分隔条 + 密排快讯卡；文章页：`nw-paper` 报纸排版（衬线标题、分隔线规整、引用块竖线）。
- 兼容既有体系：会员 / 排行榜兜底通用版、外观变量走 THEME_APPEARANCE 登记、移动端 390px 适配（快讯单列密排天然友好）。
